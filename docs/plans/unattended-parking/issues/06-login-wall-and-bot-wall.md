# 06: Login walls are "source unavailable"; bot walls are waited out and handed off

**What to build:** The browser tools recognise two kinds of page wall and tell the bot what to do, with no site named in the code. A login wall on an origin where the bot has no granted vault entry is "source unavailable": the run skips the source, says so in its report and goes on, without parking. A bot wall (Cloudflare, DataDome, PerimeterX, Imperva) is waited out for a few seconds, and if it stays, handed to me as a takeover, which parks in a routine. See the spec section "Walls" and Decision 5 in `docs/plans/grok-bot-replacement-roadmap.md`.

**Blocked by:** 04

**Status:** ready-for-agent

Nothing detects either today. `snapshotOutcome` in `browser/tools/page.ts` takes a snapshot, numbers its refs and wraps it as untrusted page content; `browser_open`, `browser_snapshot`, every action and `browser_tabs` end there. `BROWSER_INSTRUCTIONS` in `browser/tools.ts` tells the bot to call `browser_request_takeover` for a CAPTCHA, and `docs/browser.md` says only that a routine hitting a login wall "is told to say so in its run result". The password-field rules already exist in `browser/login.ts` (`FIELD`, `PASSWORD_FIELD`, `classifyAfterLogin`); share them rather than copying them. The engine's snapshot is an accessibility tree, so detection reads visible text and, from `browser_open`, the page title. `BotBrowser.exclusive` holds the bot's lane for a whole tool call and a second call waits `laneWaitMs` (30 seconds, `browser/runtime.ts`).

- [ ] A new `browser/page-walls.ts` has two pure functions over a snapshot (and an optional title): `detectBotWall` returns the vendor (`cloudflare`, `datadome`, `perimeterx`, `imperva`) or nothing; `detectLoginWall` says whether the page is a sign-in form. It names vendors, never sites. Fixtures for each vendor's interstitial text (for example "Just a moment…", "Verify you are human", "Press & Hold to confirm you are a human", "Request unsuccessful. Incapsula incident ID", the DataDome captcha page) and for benign pages are in its unit test. A long article that quotes a wall's phrase is not a wall: a marker counts only on a nearly empty page or in a heading or the title
- [ ] After `browser_open` or any call that returns a snapshot, a detected bot wall is re-snapshotted a few times with a short pause inside the call. The total pause stays well under `laneWaitMs`, and the pause comes from an option the tests can set to zero (as `laneWaitMs` is). A wall that clears returns the clear page with no note
- [ ] A wall that stays is returned with a note naming the vendor: "this page is behind <vendor> bot protection and did not clear; if the page matters, call browser_request_takeover with a one-sentence reason, then end your turn; otherwise report this source as unavailable". The host never calls the takeover itself, so a page's text cannot start one. In a routine the bot's takeover parks (ticket 04)
- [ ] A detected login wall gets a note chosen by the bot's vault coverage of the page's exact origin (`origin` in the engine's page data against `entry.origin`): a granted entry says to call `browser_login` with its label; an entry the bot has no grant for says `browser_login` will ask the owner; no entry says "source unavailable: do not try to sign in, say so in your report and continue". `BrowserLogin` gains the one function this needs (the coverage of an origin for a bot) and nothing else
- [ ] A source behind a login wall with no entry does not park and does not fail the run: a routine whose bot reports it still ends `succeeded`, and the report is the run's output
- [ ] `BROWSER_INSTRUCTIONS` and the routine prompt in `routines/index.ts` (`prompt()`) say how to report an unavailable source: a line "Unavailable: <source> (<reason>)" in the summary. `docs/browser.md` has a short section on both walls and says that no stealth browser, CAPTCHA service or proxy is used
- [ ] Tests with the fake engine's `pages` script (`testing/fake-agent-browser.ts`; the existing "login wall in a routine" test in `browser/routines.test.ts` is the prior art). The fake engine learns a page whose snapshot differs on each call (for example `pages[url].then`, the snapshots after the first), and its header comment says so. Cases: a Cloudflare page that clears on the second snapshot returns the clear page; one that stays returns the vendor note and `browser_request_takeover` then parks the routine; a sign-in page with no entry returns "source unavailable" and the routine's run is `succeeded`; the same page with a granted entry names `browser_login`; with an ungranted entry says it will ask; a benign page that mentions Cloudflare returns no note. Chat-hosted and headless. `bun run check` passes
