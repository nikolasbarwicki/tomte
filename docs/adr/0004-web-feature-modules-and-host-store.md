# 0004: Web feature modules, a host store and enforced boundaries

Status: accepted

## Context

`packages/web` was a flat folder of 20-odd files. `shell.tsx` held 14 `useState`s for the host connection and passed them to every screen through `ShellContext`, so a streamed chat token re-rendered the sidebar and the credentials screen. `reduce` lived in `transcript.tsx` next to components, so editing it forced a full reload instead of Fast Refresh. `chat.tsx` imported `BotPanel`, which imported `Routines` and the browser panel, and the router drilled a dozen props into each screen. The panel tab and the "Try it" draft lived in component state, so a reload lost them. Screens held `"/api/..."` strings, and `routines.tsx` (380 lines) and `integrations/detail.tsx` (388 lines) each mixed several concerns. The host package already follows ADR-0003; nothing gave the web package the same shape or checked it.

## Decision

- **Layout and import direction.** `packages/web/` has `main.tsx` plus config, HTML and CSS at the root, and these folders: `app/` (route tree, shell, sidebar, welcome, `routes/`), `features/<name>/` (`chat`, `bots`, `browser`, `routines`, `work`, `credentials`, `integrations`), and shared code in `host/`, `components/` (with vendored `components/ui/`), `hooks/` and `lib/`. Imports flow one way: shared → features → app. Shared code never imports features or app; features never import `app/` or each other; `components/ui/` imports only itself, `lib/`, `hooks/` and npm.
- **One `index.ts` per feature, no other barrels.** `features/<name>/index.ts` is the feature's interface, with named exports only and no `export *`. Everything else in a feature folder is private. There is no index in `components/`, `components/ui/`, `hooks/`, `lib/` or `host/`; callers import concrete files with their extension.
- **Composition by slots in `app/`.** A feature that needs another feature's UI takes it as a prop. `BotPanel` takes `work`, `tasks`, `browser`, `memory`, `routines` and `events` as `ReactNode` slots; `ChatView` takes `panel` and `rail`, each `(controls: PanelControls) => ReactNode`. `app/routes/bot.lazy.tsx` assembles `ChatView`, `BotPanel`, `Work`, `Routines`, `BrowserTab` and the rail (`app/bot-rail.tsx`). Features hold no import of one another.
- **Host store.** `host/` owns the host connection. `host/state.ts` is the pure `applyEvent(HostState, HostEvent)` reducer, unit-tested in `state.test.ts`; `host/transcript.ts` holds `Item` and `reduce` with no React. `host/store.ts` is a small external store (`get`, `subscribe`, `dispatch`) that notifies only when `applyEvent` returns a new state, and `applyEvent` returns untouched slices by reference. `host/stream.ts` turns the `EventSource` into dispatches, toasts and a reset callback, parsing each event with the contract's `HostEvent` schema (`host/api.ts` has `parseJson` and `readJson`, which throw `InvalidPayload` on a mismatch, for every HTTP response body the web reads); `Shell` starts it once. `host/hooks.ts` exposes one hook per state field (`useBots`, `useChat`, `useMemory`, …) over `useSyncExternalStore`.
- **Private selectors.** `useHost(selector)` stays private to `host/hooks.ts`, and every exported hook reads a single field, so a selector never allocates and returns a stable reference between unrelated events. Derived values (find a bot, filter, count) are computed in the component, with `useMemo` where needed. A chat token re-renders only components that read `useChat()`.
- **Screens read their own data.** Screens and panels call host hooks directly and read route state through `getRouteApi(...)` instead of receiving props. Commands go through a typed `api.ts` in each feature (and `host/api.ts` for `post`, `act`, `openBot`, `markSeen`) over `post`/`act`, so screens contain no `"/api/..."` strings; the browser live view's streaming in `useLive`/`useInput` is the exception.
- **URL search params.** `/bots/$botId` validates `{ panel?, draft? }` with zod. The panel section is `panel` (`work`, `tasks`, `browser`, `files`, `memory`, `routines`, `permissions`, `events` or `profile`; default `work`; switching navigates with `replace`), so a reload or a shared link keeps it. Links made when the panel had tabs (`panel=settings&section=routines`) are folded into `panel=<section>` by `validateSearch` (`upgradePanel` in `lib/bot-panel.ts`). "Try it" navigates to `?draft=…`; the composer seeds its input once and removes `draft` with a `replace` navigation. An invalid value is dropped, not an error. Panel open/pinned state stays in `localStorage`.
- **Lazy routes.** `app/router.tsx` is the eager route tree: paths, parents, search schemas and `.lazy()` loaders. Each screen is `app/routes/<name>.lazy.tsx` exporting `createLazyRoute(...)`, so every screen is its own chunk. Lazy route files never import `app/router.tsx`.
- **Enforcement.** `.dependency-cruiser.cjs` gains: `web-shared-not-to-features`, `web-ui-is-vendored-leaf`, `web-features-not-to-app`, `web-feature-privacy`, `web-no-cross-feature`, `web-routes-load-screens-lazily` and `web-pure-models` (`host/state.ts`, `host/transcript.ts`, `features/*/model.ts` and `features/*/schedule.ts` import no React and no `.tsx`, matched on resolved `node_modules/` paths). Each was proven by a temporary violating import that `bun run depcheck` reported. Code is fixed rather than rules loosened.
- **knip.** `knip` is a step of `bun run check` (after `fmt:check` and `lint`, before `typecheck` and `depcheck`). `knip.jsonc` at the root covers every workspace and gives `packages/web` the Vite and Tailwind plugins. Unused files, exports and dependencies in the web package are deleted or declared. The only web ignore is vendored `components/ui/**` exports and types, so later `shadcn add` diffs stay clean.

## Alternatives considered

- **One big context.** Rejected: that is `ShellContext`. Any change to any slice re-renders every consumer, which is why a chat token re-rendered the sidebar. Splitting it into one context per slice would rebuild the store by hand, without a pure reducer to test.
- **TanStack Query.** Rejected: the host pushes state over a single event stream; there is no request/response cache to manage, and the host stays authoritative. It would add a dependency and a second source of truth next to the stream.
- **Zustand (or another state library).** Rejected: `useSyncExternalStore` over a 28-line store and a pure reducer covers the need with no dependency, and keeps `applyEvent` testable under plain `bun test`.
- **Feature-Sliced Design.** Rejected: its layers (shared, entities, features, widgets, pages, app) and per-slice segments are more ceremony than six features and a composition layer need. `shared → features → app` with one `index.ts` per feature gives the same one-way rule at a size we can enforce with a few regexes.
- **File-based routing.** Rejected: code-based routes already exist, and `.lazy()` routes give the same per-screen chunks while keeping the route tree, paths and search schemas in one eager file.
- **Conventions without enforcement.** Rejected for the reason in ADR-0003: a rule only holds if a check fails when it is broken.

## Consequences

- A screen is edited in its feature folder; a new cross-feature screen means a slot in `app/routes/`, not an import between features.
- Adding a host event means one case in `applyEvent` and a test; adding a slice means a field in `HostState` and a one-line hook in `host/hooks.ts`. A hook must read a field; anything derived belongs in the component.
- New feature folders need no config change: the rules match `features/<name>/`. New top-level folders under `packages/web/` fall outside `WEB_SHARED` and need adding to `.dependency-cruiser.cjs`.
- Router state in the URL means `panel` and `draft` are public, shareable inputs and stay optional hints.
- `app/router.tsx` imports `PANEL_SECTIONS` from `lib/bot-panel.ts`, shared with the chat and bots features, so the section list is in the main chunk and no feature imports another.
- `web-routes-load-screens-lazily` only catches a screen route the router imports statically _instead of_ dynamically. dependency-cruiser keeps one edge per resolved path, so a static value or side-effect import of a `*.lazy.tsx` file that `router.tsx` also loads with `import()` is recorded as dynamic and passes the rule, while Vite silently pulls that screen into the main chunk. A type-only import is reported, which is harmless.
